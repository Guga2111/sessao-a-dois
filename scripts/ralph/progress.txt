## Codebase Patterns
- Este epico mexe SO no `client/`. Nenhuma story toca `api/`, e nenhuma muda um pixel
  do app: sao arquivos de teste, config do Vitest e um step de CI. Se uma story so
  passar alterando codigo de producao, PARAR e registrar em `notes` — a decisao e do
  mantenedor, nao do implementador (Non-Goal explicito do PRD).
- `bun` NAO vem instalado no sandbox e `bun.sh` esta inacessivel. Instalar com
  `npm install -g bun` (~3s, v1.3.14). Dependencia nova entra com `bun add -d`, nunca
  com `npm install`: `client/` versiona `bun.lock` E `package-lock.json`, o CI usa o
  `bun.lock`, e a divergencia so apareceria no CI.
- `typecheck` e `tsc -b`, nao `tsc --noEmit`: o `tsconfig.json` tem `files: []` e so
  `references`, entao `--noEmit` checa ZERO arquivos e sempre sai 0. Ver
  `client/CLAUDE.md`.
- Os testes ficam co-localizados sob `src/`, logo entram no `tsc -b` e no `eslint .`
  como codigo de producao: `strict`, `noUnusedLocals`, `noUnusedParameters`,
  `verbatimModuleSyntax` (exige `import type`) e `erasableSyntaxOnly` valem para eles.
- Duas armadilhas de escopo de modulo, ambas resolvidas com `vi.resetModules()` +
  `await import(...)`: `useAuthStore` le `localStorage` no import
  (`const initialSession = loadPersistedSession()`), e `lib/api.ts` guarda o
  `refreshPromise` do single-flight em escopo de modulo.
- O sandbox roda Node 20.20.2 (sem nvm/fnm/n — so essa versao existe). `jsdom@30`
  (o latest que `bun add -d jsdom` traz) exige Node `^22.22.2 || ^24.15.0 || >=26.0.0`
  e falha o worker do Vitest em runtime com
  `TypeError: webidl.util.markAsUncloneable is not a function` (nao e erro de
  config, e incompatibilidade do `undici` interno do jsdom com o Node do sandbox) —
  o `tsc`/`eslint` nao pegam isso, so aparece rodando `test:run`. Fixado com
  `bun add -d jsdom@29.1.1` (`engines.node: ^20.19.0 || ^22.12.0 || >=24.0.0`,
  compativel). Se `bun add`/`bun update` mexer em `jsdom` de novo, confirmar
  `bun run test:run` de verdade, nao so o typecheck/lint.
- `react-refresh/only-export-components` proibe um `.tsx` exportar componente e funcao
  comum no mesmo arquivo — vale tambem para helpers de teste.
- PRD completo em `tasks/prd-epico-11-rede-de-testes-do-frontend.md`.
