### Gotcha #1 deste epico: application.properties de teste
- `api/src/test/resources/application.properties` **SUBSTITUI** `src/main/resources/application.properties` inteiro para qualquer `@SpringBootTest` - nao mescla. Spring Boot carrega um unico application.properties por classpath root, e `test-classes` vence `classes`.
- Consequencia: TODA propriedade nova que um bean instanciado ansiosamente exige precisa ser declarada NOS DOIS arquivos. Adicionar so no principal quebra `SessaoADoisApplicationTests.contextLoads` em silencio.

### Migrations (Flyway)

- Convencoes: `IF NOT EXISTS` em tudo, sem `DROP`/`TRUNCATE`, sem default de banco em coluna `id` (`@GeneratedValue(strategy = UUID)` gera client-side).

- Deploy que aplica migration nova: `DB_URL` na porta 5432 direta ou pooler Supabase em modo Session, NUNCA modo Transaction (6543) - risco de advisory lock do Flyway, documentado em docs/FLYWAY.md.

### JPA / transacoes
- `spring.jpa.open-in-view=false` (Epico 2). A sessao do Hibernate fecha no fim do metodo `@Transactional`, nao no fim da request. Qualquer acesso LAZY fora de transacao lanca `LazyInitializationException` em vez de fazer query extra silenciosa.
- Todo metodo que le/escreve `RefreshToken` precisa ser `@Transactional`. `@Modifying @Query` exige transacao por definicao.
- Delete/update em massa: use `@Modifying @Query`, nunca o delete derivado do Spring Data (carrega tudo em memoria) - ver o que foi feito em `NotificationRepository` na T2.4.

### Testes
- Spring Boot parent 4.1.0: `@MockBean` nao existe mais. Use `@MockitoBean` (`org.springframework.test.context.bean.override.mockito.MockitoBean`).
- Entidades com `@GeneratedValue` nao tem setter de id. Em teste unitario puro, `new User(...)` tem id null e quebra qualquer comparacao de id. Use `ReflectionTestUtils.setField(entity, "id", uuid)`.
- Spring Boot 4.1.0 moveu a auto-config de seguranca para o artefato `spring-boot-security`. Classes `*AutoConfiguration` de seguranca vivem em `org.springframework.boot.security.autoconfigure.*`, NAO no pacote do Spring Boot 3.x. Verifique o pacote real antes de referenciar.

### jjwt 0.12.6 (com.app.security) - API de builder/parser
- Emitir iss/aud: `Jwts.builder().subject(...).issuer(issuer).audience().single(audience). ... .signWith(key).compact()` - `.audience()` devolve um `AudienceCollection` cujo `.single(String)` seta um unico valor de audience e retorna o builder de volta (nao precisa de `.and()`).
- Validar iss/aud no parse: `Jwts.parser().verifyWith(key).requireIssuer(issuer).requireAudience(audience).build().parseSignedClaims(token)`. Um valor de iss ou aud errado lanca `io.jsonwebtoken.IncorrectClaimException` (subclasse de `InvalidClaimException`/`JwtException`), distinto de `ExpiredJwtException`/`SignatureException`/`MalformedJwtException` ja tratados.
- Relevante para US-005 (filtro), US-006 (refresh/rotacao) e US-009 (handshake do WebSocket) - todos re-emitem ou re-parseiam tokens via `JwtService`, que agora exige `Duration accessTokenTtl`, `String issuer` e `String audience` no construtor (antes so `long expirationDays`). Qualquer teste que faz `new JwtService(secret, ...)` direto (sem contexto Spring) precisa dos 4 argumentos.
