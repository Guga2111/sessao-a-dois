## Codebase Patterns
- This sandbox has no `docker`, `java`, `mvn`, or `psql` — `./mvnw` cannot run here (no JDK). Backend "Typecheck passes"/"Tests pass" criteria that require compiling/running the Spring Boot app cannot be verified in this environment; note that limitation explicitly in progress/notes instead of silently skipping it. `api/CLAUDE.md` already documents this.
- There is no Flyway/Liquibase yet on `create-migrations`'s baseline — schema currently evolves via `spring.jpa.hibernate.ddl-auto=update`. Entities: `com.app.user.User`, `com.app.couple.Couple`, `com.app.tracking.MediaTrack` (+`media_track_genre` via `@ElementCollection`), `com.app.tracking.UserReview`, `com.app.match.MatchLike`/`MatchReject`, `com.app.notification.Notification` (new, not in `origin/main`).
- The `/ralph` skill (`.claude/skills/ralph/SKILL.md`) writes its converted `prd.json` into its own skill directory (`.claude/skills/ralph/`), which is a DIFFERENT directory from the one the running Ralph loop actually reads (`scripts/ralph/`, per `scripts/ralph/CLAUDE.md`: "same directory as this file"). If `scripts/ralph/prd.json` is ever found empty/stale after running `/ralph`, check `.claude/skills/ralph/prd.json` for the real converted content and copy it over before doing anything else — do not treat an empty `prd.json` as "PRD not ready yet" without checking there first.
- `git diff origin/main HEAD -- <entity file>` is a fast way to confirm whether a JPA entity actually changed between the deployed baseline and the current branch, instead of trusting a PRD's claims at face value.
