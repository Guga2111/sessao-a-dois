## Codebase Patterns
- Client is React + TS + Vite (Tailwind v4, CSS-based config, no tailwind.config.*), run checks with `cd client && npx tsc --noEmit` and `npx eslint <files>`.
- Dark theme colors/spacing are inlined via Tailwind arbitrary values (e.g. `bg-[#09090a]`, `text-[#ffcb2b]`) — match this pattern, don't introduce new tokens. `docs/design/claude-design-project/Sessao a Dois.dc.html` is the source of truth for exact colors/spacing.
- The project's eslint config uses `eslint-plugin-react-hooks` recommended (React Compiler-era) rules: calling `setState` synchronously inside a `useEffect` body is a lint ERROR (`react-hooks/set-state-in-effect`), and reading/writing a ref's `.current` during render is also a lint ERROR (`react-hooks/refs`). To reset a subtree's local state on route change (e.g. closing a mobile menu on navigation), extract the stateful part into its own subcomponent and mount it with `key={location.pathname}` from the parent — this remounts the subcomponent and resets its `useState` without touching effects or refs.
- No browser MCP/testing tool is available in this sandbox (checked via ToolSearch) — UI verification for these stories is limited to `tsc`/`eslint` plus manually inspecting the dev server output; flag "manual browser verification needed" in reports.

## 2026-07-23 - US-003
- Implemented: auto-pagination for the mobile Hub carousel from US-002. Added `LoadMoreSentinel` component in `HubScreen.tsx` — a 1px-wide invisible flex child rendered as the last item of a section's carousel, only when `useIsMobile()` is true and that section `hasMore`. It uses a callback ref to create one `IntersectionObserver` (threshold 0.5) per mount, disconnecting/recreating only if `status` or `onLoadMore` identity changes (both stable). The observer callback reads `hasMore`/`loadingMore` off a ref that's kept in sync via a plain `useEffect` (no deps array, no setState) — this avoids recreating the observer on every data change while still seeing fresh flags, and avoids the `react-hooks/refs` lint error (writing `ref.current` happens in an effect, never during render). Added an extra `SkeletonCard` at the end of the items list while `loadingMore` (works for both the mobile auto-load path and the desktop button path). The existing "Carregar mais" button is now `hidden md:flex` (was unconditional `flex`) so it only shows on desktop.
- Also had to make `handleLoadMore` a stable `useCallback`: previously it read `sections[status]` directly from the render closure, so a new function was created every render, which would have torn down and recreated the sentinel's IntersectionObserver on every HubScreen re-render. Added a `sectionsRef` synced via `useEffect(() => { sectionsRef.current = sections }, [sections])` and made `handleLoadMore` read `sectionsRef.current[status]` instead, with `[fetchSectionPage]` as its only dependency.
- Files changed: `client/src/screens/HubScreen.tsx`.
- **Learnings for future iterations:**
  - "Latest ref" pattern (a ref that mirrors fast-changing state/props for use inside a stable callback or observer) must sync the ref inside a `useEffect`, never inline in the render body — writing `ref.current` during render is a lint error here (`react-hooks/refs`), same as the earlier `set-state-in-effect` gotcha for setState. The effect itself has no dependency array (runs after every render) and is fine since it never calls setState.
  - When wiring an `IntersectionObserver` (or any DOM observer) to a list item that needs access to frequently-changing flags, prefer a small dedicated child component (like `LoadMoreSentinel` here) over inlining the hook logic in a `.map()` — hooks can't be called per-iteration inside a loop/map body directly.
  - `tsc --noEmit` and `eslint` both pass clean; `npm run dev` boots fine (smoke-tested). No browser tooling available in this sandbox — visual/interaction verification of the auto-load-on-scroll behavior is manual-only.

Added a `.no-scrollbar` utility (`scrollbar-width: none` + `::-webkit-scrollbar{display:none}`) to `client/src/index.css` since Tailwind v4 has no built-in scrollbar-hiding utility. `SkeletonCard` got the same mobile sizing classes so the loading state lines up horizontally too. - Files changed: `client/src/screens/HubScreen.tsx`, `client/src/index.css`.
- **Learnings for future iterations:**
  - Tailwind v4 (this project) has no scrollbar-hiding utility class built in — added `.no-scrollbar` to `index.css`, reuse it for any other future horizontal-scroll UI instead of duplicating the CSS.
  - `MediaCard` (`client/src/components/MediaCard.tsx`) does not accept a `className` prop — to control a card's outer sizing (e.g. carousel width) wrap it in a plain `<div>` rather than trying to pass classes through.
  - Arbitrary Tailwind properties not covered by named utilities (e.g. `scroll-snap-align`, `overscroll-behavior-x`) work fine as bracket syntax like `[scroll-snap-align:start]` and can be breakpoint-prefixed (`md:[scroll-snap-align:none]`) same as any other utility.
