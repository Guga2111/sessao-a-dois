- **Learnings for future iterations:**
  - Every feature package in this backend gets its own `@RestControllerAdvice(basePackages = "com.app.X")` handler that maps `com.app.tracking.ResourceNotFoundException` -> 404 and `org.springframework.security.access.AccessDeniedException` -> 403 (see TrackingExceptionHandler/MatchExceptionHandler). Reuse this exact pattern rather than inventing a new exception type per feature.
  - `com.app.tracking.ResourceNotFoundException` is a shared cross-feature class (already imported by com.app.match) - it's fine to reuse from com.app.notification too instead of creating a notification-specific one.
  - For a "mark all as read/done" bulk update, prefer a `@Modifying @Query("UPDATE ... SET ... WHERE ...")` on the repository (needs the calling service method annotated `@Transactional`) over fetching all rows and calling save() in a loop.
  - When a DTO/list endpoint needs a display name resolved from a foreign id per row (e.g. actorName from actorUserId), batch-resolve with `userRepository.findAllById(distinctIds)` into a Map first, then map over the page - avoids N+1 UserRepository.findById calls per row.
  - This sandbox has no JDK/Maven and no network access to Maven Central (mvnw tries to download the maven distribution and fails) - consistent with the note already in api/CLAUDE.md. Changes here were verified by manual code review only, not by running ./mvnw test. Flag this to a human or a later iteration with build tooling available.
