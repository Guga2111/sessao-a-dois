## Codebase Patterns
- User references on entities scoped to a Couple (recipientUserId, actorUserId, MatchLike.userId) are plain UUID @Column fields, not @ManyToOne to User — only the Couple relation is a real JPA association.
- This sandbox has no JDK/Maven (`mvn`/`java` missing, `./mvnw` can't reach Maven Central) — backend changes here cannot be compiled/tested locally; mirror existing tested code closely and flag verification as pending.
- Derived Spring Data `deleteBy...` repository methods (e.g. `deleteByCreatedAtBefore`) return a long/int count of deleted rows and need no `@Modifying` — just call them from a `@Transactional` service method.
- `@CreationTimestamp` fields (like `Notification.createdAt`) can't be set via the constructor in tests; use `ReflectionTestUtils.setField(entity, "createdAt", ...)` after `save()` (then `saveAll`) to backdate a row for retention/expiry tests.

- **Learnings for future iterations:**
  - Followed the MatchLike convention: recipientUserId/actorUserId are plain UUID @Column fields (conceptually FK to User), not @ManyToOne relations to User — only Couple gets a real @ManyToOne. Reuse this for any future notification-related entity.
  - Avoided naming a column `read` (SQL ambiguous/reserved-ish keyword) — mapped the boolean field `read`/`isRead()` to column `is_read` instead. If a future story queries this column directly (native SQL or a raw @Query string), remember it's `is_read` on the DB side.
  - Composite index for the "list unread notifications for a user" access pattern is declared via `@Table(indexes = @Index(columnList = "recipient_user_id, is_read"))` on the entity, consistent with how MatchLike/MediaTrack express table-level constraints in this codebase (e.g. MatchLike's @UniqueConstraint).

Code was written to mirror MatchLikeRepositoryTest/MatchLike exactly (same annotations, same @DataJpaTest + CoupleRepository helper pattern) to minimize risk. Future iterations in this sandbox will hit the same limitation — verify on a machine with JDK 21 + Maven Central access before merging if this matters.
