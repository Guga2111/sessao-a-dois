## Codebase Patterns
- Backend package base is `com.app` (package-by-feature): user, couple, media, tracking, match, notification, security, websocket.
- Notifications: `NotificationService.notifyCouple(...)` is the single entry point today; it persists one Notification per couple member and pushes STOMP to `/topic/couple/{coupleId}/notifications` via `TransactionSynchronizationManager.afterCommit()`. Reuse the persist-then-push-after-commit pattern.
- Enums on entities are always `@Enumerated(EnumType.STRING)`, so adding an enum constant needs no data migration.
- `api/src/test/resources/application.properties` REPLACES the main one for `@SpringBootTest`; any new required property must be mirrored there.
- **This sandbox has no JDK and no Maven Central access** (`java` not found, `./mvnw` cannot download Maven). Backend compile/test acceptance criteria cannot be verified here — keep changes conservative and flag verification as pending in the progress log.
- Frontend rule (CLAUDE.md): any change under `client/` must invoke the `frontend-design` skill first.
