## Codebase Patterns
- No JDK 21 / Maven Central in this sandbox: `java` is absent and `./mvnw` cannot download Maven. Backend build/test (`./mvnw test`) can only be verified on a machine with JDK 21 + Maven Central access. Make correct changes and note verification is deferred.
- Base Java package is `com.app`; Maven `groupId` stays `com.lf` (intentional). See api/CLAUDE.md.
- Test `src/test/resources/application.properties` REPLACES the main one for `@SpringBootTest` — redeclare every required property (`tmdb.api-key`, `app.jwt.secret`).
- Unit-test the shared TMDB `RestClient` with `Mockito.mock(RestClient.class, RETURNS_DEEP_STUBS)` and stub the terminal `.body(Type.class)`.
- Entities with `@GeneratedValue` ids have no id setter; use `ReflectionTestUtils.setField(entity, "id", uuid)` in unit tests.
- No `docker`/`docker compose` binary in this sandbox either — `docker compose ... config` validation is DEFERRED to a Docker host. Env var names the API expects (from `api/src/main/resources/application.properties`): `DB_URL`, `DB_USER`, `DB_PASSWORD`, `JWT_SECRET`, `JWT_EXPIRATION_DAYS`, `CORS_ALLOWED_ORIGIN`, `TMDB_BASE_URL`, `TMDB_API_KEY`. Spring Boot server port is the default `8080` inside the container (not overridden), so host publishes `${API_PORT:-8085}:8080`.
- Compose healthcheck gotcha: to reference a container-side env var inside a `CMD-SHELL` healthcheck, escape with `$$` (e.g. `pg_isready -U $${POSTGRES_USER}`) so compose does not interpolate it at parse time. `eclipse-temurin:21-jre` (Ubuntu base) has `bash`, so `bash -c 'echo > /dev/tcp/127.0.0.1/8080'` is a dependency-free TCP healthcheck (no Actuator/curl needed).
- Frontend `vite build` in this sandbox CAN run after installing the missing native bindings for THIS arch (linux-arm64-gnu) as `--no-save` (all in ONE `npm i` — a second install dedupes/wipes the first): `npm i lightningcss-linux-arm64-gnu@<lightningcss ver> @rolldown/binding-linux-arm64-gnu@<rolldown ver> @tailwindcss/oxide-linux-arm64-gnu@<oxide ver> --no-save` (read each version from `node_modules/<pkg>/package.json`). Then `npx vite build` succeeds. `npx tsc --noEmit` / `tsc -b` and `eslint` always work. No `bun` binary — use `npx`. (Supersedes the older client/CLAUDE.md note that the build could not run.)
- Vite bakes `import.meta.env.VITE_*` at build time from `client/.env.production` (git-ignored via `.env.*`). After a prod build, `sockjs-client` still embeds harmless `http://localhost` / `http://localhost:80` fallback strings in the bundle (library internals, used only if `window.location` is unavailable) — the real check is that the dev API port (`8080`/`8085`) is ABSENT and the prod host IS present.
