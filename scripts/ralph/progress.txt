## Codebase Patterns
- Backend package-by-feature under `com.app.*` (see `api/CLAUDE.md`); new features get their own package (e.g. `com.app.websocket`, `com.app.match`).
- `SecurityConfig` (com.app.security) applies `anyRequest().authenticated()` to everything not explicitly `permitAll()`'d — any new public-ish endpoint (including non-REST ones like the STOMP handshake `/ws/**`) needs an explicit `requestMatchers(...).permitAll()` entry, then do its own auth inside (e.g. a `HandshakeInterceptor` reading a JWT).
- Browser WebSocket/SockJS handshakes cannot set the `Authorization` header, so JWT for `/ws` is passed as a `?token=` query param and validated in a `HandshakeInterceptor` (`com.app.websocket.JwtHandshakeInterceptor`), not via the existing `JwtAuthenticationFilter`.
- This sandbox has no JDK/Maven and no Maven Central access (`./mvnw` fails trying to download the wrapper distribution) — backend changes here can only be reviewed by careful manual reading, not compiled/tested locally. Flag this explicitly in each backend story's progress entry rather than claiming "tests pass".

- **Learnings for future iterations:**
  - **`@RestControllerAdvice(basePackages = "...")` is scoped by the *controller's* package, not the exception's origin package.** If a controller in package X throws an exception class defined in package Y, and Y's own `@RestControllerAdvice` is `basePackages`-scoped to Y, that advice will NOT catch the exception when thrown from X's controller — you get an unhandled 500 instead of the expected status. Either scope the advice more broadly, or (as done here) add a handler for the shared exception type in X's own advice too.
