## Codebase Patterns
- Plain (non-base-ui) primitives like `Skeleton` follow `card.tsx`'s shape: `import * as React from "react"`, a single function component typed `React.ComponentProps<"div">`, `data-slot="..."` on the root, `cn(...)` merging default classes with `className`. No CVA needed unless there are real variants.
- Theme is dark-prototype-driven: cards use `bg-[#161513]`, `border-[rgba(255,255,255,.07)]`, `rounded-[18px]`; inner placeholder/skeleton blocks use `bg-white/[0.06]`. Source of truth is `docs/design/claude-design-project/Sessao a Dois.dc.html`.
- `tsc --noEmit` and `npx eslint <file>` both run cleanly from `client/` with no extra flags needed for quick per-file checks.

## 2026-07-29 - US-002
- Implemented `src/lib/useDelayedLoading.ts`: hook `useDelayedLoading(loading, { delayMs = 150, minVisibleMs = 400 })` returning `showSkeleton: boolean`, using a `shownAtRef` timestamp ref plus one `setTimeout` per effect run (show-timer when `loading` turns true, hide-timer computed from `minVisibleMs - elapsed` when it turns false).
- Files changed: `client/src/lib/useDelayedLoading.ts` (new).
- **Learnings for future iterations:**
  - All `setShowSkeleton(...)` calls live inside the `setTimeout` callback, never as a direct statement in the effect body, so `react-hooks/set-state-in-effect` doesn't fire — same pattern as the `client/CLAUDE.md` "fetching data on mount" gotcha, just applied to a boolean-toggle hook instead of a fetch.
  - When `loading` flips to `false` before `shownAtRef.current` was ever set (skeleton never became visible because it resolved faster than `delayMs`), the effect returns early with no `setState` call at all — `showSkeleton` is already `false`, so there's nothing to reset and no direct-call lint risk.
  - Every effect branch returns a cleanup that clears its own timer, so unmounting or re-triggering (`loading` flips again before a timer fires) never lets a stale timer call `setState` after the fact.
  - This is a plain hook with no visible UI, so it didn't need the `frontend-design` skill — reserve that skill for stories where output renders in the browser (US-003 onward).

- Files changed: `client/src/screens/HubScreen.tsx`.
- **Learnings for future iterations:**
  - When a screen has a small **fixed** set of parallel loading flags (here, 3 known `MediaStatus` values), call `useDelayedLoading` once per fixed key directly in the component body (not inside `.map()` or dynamically) and collect the results into a `Record<Key, boolean>` — keeps hook call order stable across renders while still supporting per-section anti-flicker state.
  - `MediaCardSkeleton` renders fine standalone outside the grid (e.g. in the desktop load-more slot) as long as it's wrapped in a fixed-width container (`w-[220px]` used here) — its own classes assume either a flex/grid item context or an explicit width, it has no default block width.
  - This story was pure wiring of already-existing components (`MediaCardSkeleton` from US-003, `useDelayedLoading` from US-002) into an already-existing conditional-render structure — no new visual language, so the `frontend-design` skill invocation confirmed reuse-as-is rather than producing new design decisions.
