## Codebase Patterns
- `client/`: dark theme prototype colors are historically inlined via Tailwind arbitrary values (`bg-[#161513]`, etc.) — see `client/CLAUDE.md`. As of Epico 13/US-001, `client/src/index.css` now carries the *real* brand palette as semantic tokens (`.dark` block), so future color-migration stories (US-003+) should map hex -> token per the list in that file's comment, not invent new arbitrary values.
- The app is dark-only in practice (D17, `POST-MVP-TASK.md`): the `ThemeProvider`/`d`-key toggle to light mode still exists in code but produces a broken UI, since every screen hardcodes dark hex regardless of theme. Removing that toggle is a separate future story (T13.3) — don't touch `:root` (light) tokens for color-migration work, only `.dark`.
- Hex/oklch round-trip check: convert with the standard sRGB<->OKLCH matrices (D65, CSS Color 4), round L/C/H to 3 decimals, then convert back and diff per-channel — 1 unit of rounding tolerance is expected and acceptable.
- `bun run typecheck`/`lint`/`test:run`/`build` are all run from `client/` (that's where `package.json` lives), not the repo root.

## 2026-08-13 - US-002
- Implemented: CI gate against new raw color literals outside `client/src/components/ui/`.
  - `client/scripts/check-color-literals.mjs`: walks `src/**/*.{ts,tsx}` (skipping `components/ui/` — permanently exempt — and test files: `*.test.tsx`/`*.spec.tsx`/anything under a `test/` dir), flags `#rrggbb` hex literals and arbitrary Tailwind color utilities (`bg-[...]`/`text-[...]`/`border-[...]`/`ring-[...]`/`from-[...]`/`to-[...]`/`via-[...]`/`shadow-[...]`/`fill-[...]`/`stroke-[...]`). Any hit in a file NOT listed in `color-migration-allowlist.txt` fails with exit 1 and a per-hit message naming the semantic token to use instead (built from the 8 tokens established in US-001: `--background`/`--foreground`/`--card`/`--primary`/`--muted-foreground`/`--accent`/`--destructive`/`--destructive-foreground`); unknown hex values get a generic "no known token, add one to index.css" message instead of silently allowing a new arbitrary value. `--list-offenders` flag prints the raw file list with no allowlist/exit-code enforcement, for regenerating the allowlist.
  - `client/color-migration-allowlist.txt`: the 54 files that currently have hex/arbitrary color (generated via `--list-offenders`, not hand-written), top comment declaring it's temporary debt/the migration scoreboard, and that the PR removing the last line closes the migration.
  - `package.json`: new `check:colors` script (`node scripts/check-color-literals.mjs`).
  - `.github/workflows/ci.yml`: new `Check for raw color literals` step in the `frontend` job, between `Lint` and `Test` — same "gate, no continue-on-error" posture as `Audit dependencies`/`Test`.
- Files changed: `client/scripts/check-color-literals.mjs` (new), `client/color-migration-allowlist.txt` (new), `client/package.json`, `.github/workflows/ci.yml`, `client/CLAUDE.md`, `scripts/ralph/prd.json`.
