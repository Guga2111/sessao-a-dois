## Codebase Patterns
- Backend: package-by-feature under `com.app.<feature>` (e.g. `com.app.user`), see docs/ARCHITECTURE.md.
- `spring.jpa.hibernate.ddl-auto=update` (api/src/main/resources/application.properties) — no manual migrations; entities drive schema creation against the dev PostgreSQL.
- This sandbox has no JDK/`java`/`mvn` and no network access to Maven Central — `./mvnw` cannot be run here (see api/CLAUDE.md). Implement carefully and double-check imports/APIs by hand; a JDK-enabled environment must verify the build before merge.
- For repository-level JPA tests, use `@DataJpaTest` with the `com.h2database:h2` dependency added in test scope (api/pom.xml) — Spring Boot auto-swaps in an embedded DB, no extra config needed.

- **Learnings for future iterations:**
  - This project pins Spring Boot parent `4.1.0`, where `@MockBean`/`org.springframework.boot.test.mock.mockito.MockBean` is gone — use `@MockitoBean` from `org.springframework.test.context.bean.override.mockito.MockitoBean` instead in any new `@WebMvcTest`/`@SpringBootTest`.
  - `@WebMvcTest` does NOT load unrelated `@Configuration` classes (like `com.app.security.SecurityConfig`) by default, and Spring Security's own test auto-config will 401 unauthenticated requests if no `SecurityFilterChain` bean is present in the slice. Add `@Import(SecurityConfig.class)` to any `@WebMvcTest` that exercises an endpoint, so the slice matches the real runtime security config (permit-all placeholder for now; will still be needed once US-004 adds real auth rules, since public routes like `/api/auth/register` stay permitAll).
  - `AuthExceptionHandler` is a `@RestControllerAdvice(basePackages = "com.app.auth")`; `@WebMvcTest` auto-detects it without extra wiring.
  - Still no JDK/`mvn`/network in this sandbox — could not run `./mvnw test`. Re-verify with a real JDK 21 environment before merge.
