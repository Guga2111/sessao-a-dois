## Codebase Patterns
- Backend: `./mvnw -B test` is the gate; it also runs JaCoCo (min 90% line coverage on BUNDLE). A build is not done until this is green.
- `api/src/test/resources/application.properties` REPLACES (not merges with) `api/src/main/resources/application.properties` for any `@SpringBootTest`. Any new property an eagerly-instantiated bean depends on must be mirrored there.
- Before referencing any Spring Boot 4.1 auto-configuration/endpoint class by name, verify the real package in the jar first (`unzip -l ~/.m2/repository/org/springframework/boot/<artifact>/4.1.0/*.jar | grep <Class>`) — Boot 4.1 moved packages around vs. 3.x docs/examples.
- `SecurityConfig` applies `anyRequest().authenticated()`, which runs at the Spring Security filter level BEFORE DispatcherServlet tries to map a route. So an unmapped route under a closed `/actuator/**` exposure still returns 401 (via the app's `authenticationEntryPoint`), not 404 — test the status the app actually returns, don't assume 404 just because "nothing is mapped there".
- A `@SpringBootTest @AutoConfigureMockMvc` test that does NOT call `SecurityMockMvcRequestPostProcessors.csrf()` does not need `@DirtiesContext` — the context-poisoning gotcha documented on `SecurityConfigTest` only applies to tests that use that specific helper.

  - The health-check executor pattern (small fixed daemon-thread pool + `Future.get(timeout)` + swallow-and-return-false on any exception) is the template for any future probe that must never let a hung dependency block the calling thread indefinitely or leak non-daemon threads — see `HealthCheckExecutorConfig`.

## 2026-08-12 - US-003
- Implemented: `POST /api/client-errors` — a new, public, unauthenticated endpoint that receives client-side render-error reports and writes them to the backend log at `warn` level, so a "went all white" report can be investigated later via the correlation id.
- Files changed:
  - `api/src/main/java/com/app/observability/ClientErrorRequest.java` (new): Bean Validation record — `message` `@NotBlank` + `@Size(max=500)`; `stack`/`route`/`userAgent` all optional, `@Size(max=4000)`/`@Size(max=300)`/`@Size(max=300)` respectively (`@Size` alone is a no-op on `null`, so the three stay optional without needing `@NotNull`).
  - `api/src/main/java/com/app/observability/ClientErrorLogger.java` (new): the single formatter, same one-class-formats-the-line shape as `com.app.security.SecurityAuditLogger`. Reads the correlation id from `MDC.get(CorrelationIdFilter.MDC_KEY)` (no new correlation mechanism). Every field passes through a private `sanitize` (`value.replaceAll("[\\p{Cntrl}]", " ").trim()`) before being quoted into the line — `\p{Cntrl}` covers `\r`/`\n` and other control chars, which is the log-forging defense the AC calls for on a public, unauthenticated, log-writing endpoint. Emits `event=client_error correlationId=... route="..." message="..."` always, plus `userAgent="..."`/`stack="..."` when present (the AC's literal format template only shows `route`/`message`, but `stack` is exactly the thing an investigator needs and the format is additive/key=value like `SecurityAuditLogger`, so nothing about the required substrings breaks by adding more fields).
  - `api/src/main/java/com/app/observability/ClientErrorController.java` (new): `@PostMapping` taking `@Valid @RequestBody ClientErrorRequest`, delegates to `ClientErrorLogger`, returns `204` with an empty body via `ResponseEntity.noContent().build()`. No business logic in the controller itself (mirrors `NotificationController`'s thinness).
  - `api/src/main/java/com/app/security/SecurityConfig.java`: added `"/api/client-errors"` to the CSRF `ignoringRequestMatchers` list, and `.requestMatchers(HttpMethod.POST, "/api/client-errors").permitAll()` next to the existing `GET /api/health` permitAll line (E12.5).

  - `api/CLAUDE.md`: new bullet documenting the package, the sanitize-before-log defense, the two `SecurityConfig` lines this route needed, and a heads-up that US-004 (rate limit) will add a `CLIENT_ERRORS` entry to `RateLimitFilter`'s enum next — nothing here should need to change for that.

Four tests: success → `204` with an empty body, `message` over 500 chars → `400` whose body does NOT contain the oversized string (no echo, proven via `GlobalExceptionHandler`'s existing `MethodArgumentNotValidException` handler — auto-detected by the `@WebMvcTest` slice, no `@Import` needed), anonymous request accepted + `verifyNoInteractions(jwtService)`, and a `ListAppender` on the root logger (same pattern as `MediaTrackQueryCountTest`) asserting the emitted line contains `event=client_error`, the correlation id sent via `X-Request-Id`, the route and the message.
  - `scripts/ralph/prd.json`: US-003 `passes` set to `true`.
- Verification: `./mvnw -B test` — 584 tests, 0 failures, 0 errors, JaCoCo coverage check passed, BUILD SUCCESS. Ran `ClientErrorControllerTest` alone first (4/4 green) and inspected the captured log lines in stdout to confirm the exact format before running the full suite.
- **Learnings for future iterations:**
  - `com.app.observability` is the first package in this app where the security-slice standard `@Import` set needs an extra real (non-mocked) feature bean (`ClientErrorLogger`) alongside it, because the thing under test IS the log line — mocking the logger would make the log-line assertion vacuous.
