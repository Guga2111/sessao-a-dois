## Codebase Patterns
- Backend: `./mvnw -B test` is the gate; it also runs JaCoCo (min 90% line coverage on BUNDLE). A build is not done until this is green.
- `api/src/test/resources/application.properties` REPLACES (not merges with) `api/src/main/resources/application.properties` for any `@SpringBootTest`. Any new property an eagerly-instantiated bean depends on must be mirrored there.
- Before referencing any Spring Boot 4.1 auto-configuration/endpoint class by name, verify the real package in the jar first (`unzip -l ~/.m2/repository/org/springframework/boot/<artifact>/4.1.0/*.jar | grep <Class>`) — Boot 4.1 moved packages around vs. 3.x docs/examples.
- `SecurityConfig` applies `anyRequest().authenticated()`, which runs at the Spring Security filter level BEFORE DispatcherServlet tries to map a route. So an unmapped route under a closed `/actuator/**` exposure still returns 401 (via the app's `authenticationEntryPoint`), not 404 — test the status the app actually returns, don't assume 404 just because "nothing is mapped there".
- A `@SpringBootTest @AutoConfigureMockMvc` test that does NOT call `SecurityMockMvcRequestPostProcessors.csrf()` does not need `@DirtiesContext` — the context-poisoning gotcha documented on `SecurityConfigTest` only applies to tests that use that specific helper.

## 2026-08-12 - US-002
- Implemented: `GET /api/health` now delegates to the Actuator `HealthEndpoint` bean instead of returning a constant `{"status":"UP"}`. Database up returns 200 `{"status":"UP","db":"UP"}`; database down (or a check that hangs) returns 503 `{"status":"DOWN","db":"DOWN"}` in bounded time, with no credential/URL/stack-trace leakage.
- Files changed:
  - `api/src/main/java/com/app/HealthController.java`: constructor now takes `HealthEndpoint` + a qualified `ExecutorService` (`HealthCheckExecutorConfig.EXECUTOR_BEAN_NAME`). `isDatabaseUp()` submits `healthEndpoint.health().getStatus()` to that executor and waits at most `TIMEOUT_MILLIS = 2000` via `Future.get(timeout, unit)`; any exception (timeout, check failure) just yields `false` — no exception detail ever reaches the response, only the two fixed `UP_BODY`/`DOWN_BODY` constants.
  - `api/src/main/java/com/app/HealthCheckExecutorConfig.java` (new): `@Configuration` exposing the `healthCheckExecutor` bean — `Executors.newFixedThreadPool(2, daemonThreadFactory)`, threads named `health-check-N` and daemon so a hung DB check never blocks JVM shutdown or accumulates non-daemon threads across probes (container every 30s + external monitor every 5min).
  - `api/src/test/java/com/app/HealthControllerTest.java`: rewritten. Because `HealthEndpoint`'s return type (`HealthDescriptor`/sealed types under it) can't be mocked by Mockito ("Sealed interfaces or abstract classes can't be mocked"), the test builds a **real** `HealthEndpoint` bean (`FakeHealthEndpointConfig`, `@TestConfiguration`) wired to a real `DefaultHealthContributorRegistry` with a single fake `HealthIndicator` ("db") whose `Health` is swapped per-test via a static `AtomicReference<Supplier<Health>>` (`DB_HEALTH`). Three new tests: DB up → 200, DB down (indicator throws with a fake JDBC URL/credentials baked into the exception message) → 503 with an explicit `assertThat(body).doesNotContainIgnoringCase(...)` for `jdbc`/`postgres`/`password`/`secret`/`exception`/`db-host`, and DB check that sleeps 5s → 503 in well under the full 5s (asserted `< 4000ms`, i.e. it returns close to the 2s executor timeout, not the 5s the hung check would take). `@Import` gained `HealthCheckExecutorConfig.class` alongside the existing security beans.
  - `scripts/ralph/prd.json`: US-002 `passes` set to `true`.
- Verification: `./mvnw -B test` — 580 tests, 0 failures, 0 errors, JaCoCo coverage check passed, BUILD SUCCESS. Confirmed `SecurityConfig` untouched (`/api/health` still `permitAll` + still in the CSRF `ignoringRequestMatchers` list) and `spring.datasource.hikari.connection-timeout` is not set anywhere in `application.properties` (main or test) — the default 30s stands, only the health-probe's own executor has the 2s budget.
- **Cascade effect (per AC, recorded here as required):** with the database down, `api/Dockerfile`'s `HEALTHCHECK` (`wget -qO- http://localhost:8080/api/health`, `--interval=30s --timeout=3s`) now marks the container `unhealthy` instead of staying falsely `healthy`, and `.github/workflows/deploy.yml`'s "Smoke test do endpoint publico de health" step (`curl -fsS "${APP_URL}/api/health"`) now fails the deploy on a genuinely broken database instead of passing on a hardcoded 200. Both are the intended, desired change — the second one changes what counts as a successful deploy from here on.
- **Learnings for future iterations:**
  - `HealthEndpoint`'s public return type is Boot 4.1's sealed `HealthDescriptor` hierarchy — Mockito cannot mock it. Any future test needing a controllable `HealthEndpoint` must build a real one against a real `DefaultHealthContributorRegistry` with a fake `HealthIndicator`, following `HealthControllerTest.FakeHealthEndpointConfig` as the template, rather than trying `@MockitoBean HealthEndpoint`.
  - `management.endpoints.web.exposure.include=` (empty, from US-001) only controls the HTTP mapping under `/actuator/**` — the `HealthEndpoint` bean itself is still fully available for injection and direct invocation by application code (`HealthController` here), which is exactly the point of US-001 laying that groundwork.
  - The health-check executor pattern (small fixed daemon-thread pool + `Future.get(timeout)` + swallow-and-return-false on any exception) is the template for any future probe that must never let a hung dependency block the calling thread indefinitely or leak non-daemon threads — see `HealthCheckExecutorConfig`.
