## 2026-07-20 - US-002
- Implemented GET /api/media/search?q={termo} in com.app.media: MediaController delegates to MediaSearchService, which calls TMDB's /search/multi via the shared tmdbRestClient bean (from TmdbConfig, US-001) and maps results to a simplified public DTO.
- Added package-private raw TMDB DTOs (TmdbMultiSearchResponse, TmdbMultiSearchItem) with @JsonProperty for snake_case fields (media_type, release_date, first_air_date, poster_path, vote_average) and @JsonIgnoreProperties(ignoreUnknown = true) since TMDB returns extra fields (page, total_pages, etc.) and "person" items with a different shape.
- Public DTO MediaSearchResult(tmdbId, mediaType, title, year, posterUrl, overview, voteAverage); MediaType enum (MOVIE, TV). Items with media_type outside movie/tv (e.g. person) are filtered out in MediaSearchService.search().
- Poster URL built as "https://image.tmdb.org/t/p/w500" + poster_path (null-safe, returns null if TMDB has no poster_path). Year extracted from release_date (movies) / first_air_date (tv) by parsing the first 4 chars, null-safe if the date is missing/malformed.
- Empty/missing `q` -> InvalidSearchQueryException, mapped by new MediaExceptionHandler (@RestControllerAdvice(basePackages = "com.app.media")) to 400 with {"message": ...} BEFORE calling the service/TMDB, per acceptance criteria. Empty TMDB result list is NOT an error - returns 200 with [].
- Endpoint requires authentication (no permitAll added for /api/media/** - it inherits anyRequest().authenticated() from SecurityConfig, consistent with the rest of the authenticated app).
- Files changed: api/src/main/java/com/app/media/{MediaType,MediaSearchResult,TmdbMultiSearchResponse,TmdbMultiSearchItem,InvalidSearchQueryException,MediaExceptionHandler,MediaSearchService,MediaController}.java (new), api/src/test/java/com/app/media/{MediaSearchServiceTest,MediaControllerTest}.java (new), api/CLAUDE.md, scripts/ralph/prd.json.
- **Learnings for future iterations:**
  - Testing a service built around the shared RestClient bean: mock with `Mockito.mock(RestClient.class, RETURNS_DEEP_STUBS)` and stub only the terminal `.body(SomeType.class)` call, e.g. `when(restClient.get().uri(any(Function.class)).retrieve().body(X.class)).thenReturn(...)` - the `uri(Function<UriBuilder,URI>)` lambda passed by production code is never invoked against a real UriBuilder in this setup (deep stub short-circuits it), so the matcher just needs `any(Function.class)`.
  - @WebMvcTest for an authenticated com.app.* controller: `@Import(SecurityConfig.class)` + `@MockitoBean JwtService` is enough (JwtAuthenticationFilter is a real @Component and gets picked up); use `.with(authentication(new UsernamePasswordAuthenticationToken(userId, null, List.of())))` from spring-security-test to simulate an authenticated caller, and a plain unauthenticated request to assert 401. See CoupleControllerTest for the reference pattern.

## 2026-07-21 - US-003
- Implemented GET /api/media/{mediaType}/{tmdbId} (mediaType = movie|tv) in com.app.media: MediaController delegates to MediaDetailsService, which calls TMDB's GET /{mediaType}/{tmdbId}?append_to_response=watch/providers via the shared tmdbRestClient bean (from TmdbConfig, US-001) in a single HTTP call.
- Added raw TMDB DTOs (TmdbMediaDetailsResponse, TmdbGenre, TmdbWatchProvidersResponse, TmdbWatchProviderCountry, TmdbWatchProviderEntry) mapping snake_case fields via @JsonProperty, including the composite `watch/providers` key from append_to_response. Public DTOs: MediaDetails(tmdbId, mediaType, title, year, posterUrl, overview, genres, voteAverage, runtime, watchProviders) and WatchProvider(name, logoUrl).
- watchProviders extraction reads `results.BR.flatrate` from the TMDB response; returns an empty list (not an error) when Brazil has no data or watch/providers is absent entirely. runtime is only populated for movies (null for tv).
- MediaType gained `fromPathValue(String)` which throws InvalidMediaTypeException for anything other than movie/tv - this runs in the controller BEFORE calling MediaDetailsService/TMDB, satisfying the "400 before calling TMDB" acceptance criterion. MediaNotFoundException wraps a TMDB 404 (caught as HttpClientErrorException.NotFound around the RestClient call) and is mapped to a 404 response. Both exceptions are handled by the existing MediaExceptionHandler (@RestControllerAdvice(basePackages = "com.app.media")), same pattern as InvalidSearchQueryException from US-002.
