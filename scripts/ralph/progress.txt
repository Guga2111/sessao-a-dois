## Codebase Patterns
- Backend: package-by-feature under `com.app.<feature>` (e.g. `com.app.user`), see docs/ARCHITECTURE.md.
- `spring.jpa.hibernate.ddl-auto=update` (api/src/main/resources/application.properties) — no manual migrations; entities drive schema creation against the dev PostgreSQL.
- This sandbox has no JDK/`java`/`mvn` and no network access to Maven Central — `./mvnw` cannot be run here (see api/CLAUDE.md). Implement carefully and double-check imports/APIs by hand; a JDK-enabled environment must verify the build before merge.
- For repository-level JPA tests, use `@DataJpaTest` with the `com.h2database:h2` dependency added in test scope (api/pom.xml) — Spring Boot auto-swaps in an embedded DB, no extra config needed.

- **Learnings for future iterations:**
  - This project pins Spring Boot parent `4.1.0`, where `@MockBean`/`org.springframework.boot.test.mock.mockito.MockBean` is gone — use `@MockitoBean` from `org.springframework.test.context.bean.override.mockito.MockitoBean` instead in any new `@WebMvcTest`/`@SpringBootTest`.
  - `@WebMvcTest` does NOT load unrelated `@Configuration` classes (like `com.app.security.SecurityConfig`) by default, and Spring Security's own test auto-config will 401 unauthenticated requests if no `SecurityFilterChain` bean is present in the slice. Add `@Import(SecurityConfig.class)` to any `@WebMvcTest` that exercises an endpoint, so the slice matches the real runtime security config (permit-all placeholder for now; will still be needed once US-004 adds real auth rules, since public routes like `/api/auth/register` stay permitAll).
  - `AuthExceptionHandler` is a `@RestControllerAdvice(basePackages = "com.app.auth")`; `@WebMvcTest` auto-detects it without extra wiring.
  - Still no JDK/`mvn`/network in this sandbox — could not run `./mvnw test`. Re-verify with a real JDK 21 environment before merge.

Secret/expiration read via `@Value` from `app.jwt.secret` / `app.jwt.expiration-days` (application.properties, env-overridable via `JWT_SECRET`/`JWT_EXPIRATION_DAYS`; dev default secret is a placeholder >=32 bytes for HS256).
- Added POST `/api/auth/login` (`AuthController`): `AuthService.login(LoginRequest)` looks up by email, checks `PasswordEncoder.matches`, throws `InvalidCredentialsException` (401, generic message, same for wrong password and unknown email) otherwise returns `AuthService.LoginResult(token, user)`. Controller wraps that into `LoginResponse(token, UserSummary, couple)`.
- `LoginResponse.couple` is always `null` for now — the `Couple` entity doesn't exist yet (US-005/US-006 of this epic will populate it). Kept the field as `Object` so it can be swapped for a real `CoupleSummary` type later without changing the response shape.
- Files changed: api/pom.xml, api/src/main/resources/application.properties, api/src/main/java/com/app/security/JwtService.java (new), api/src/main/java/com/app/auth/{AuthController,AuthService,AuthExceptionHandler}.java, api/src/main/java/com/app/auth/{LoginRequest,LoginResponse,UserSummary,InvalidCredentialsException}.java (new), api/src/test/java/com/app/auth/{AuthServiceTest,AuthControllerTest}.java, scripts/ralph/prd.json.
- **Learnings for future iterations:**
  - jjwt 0.12.x API: build a `SecretKey` with `Keys.hmacShaKeyFor(secretBytes)` (needs >=32 bytes for HS256), then `Jwts.builder().subject(...).issuedAt(...).expiration(...).signWith(key).compact()`; parse with `Jwts.parser().verifyWith(key).build().parseSignedClaims(token).getPayload()`. Needs three deps: `jjwt-api` (compile) + `jjwt-impl` + `jjwt-jackson` (both runtime scope).
  - `AuthService` now takes 3 constructor args (`UserRepository`, `PasswordEncoder`, `JwtService`) — any test/config constructing it directly needs updating (done in `AuthServiceTest`).
  - US-004 (Spring Security + JWT filter) can reuse `JwtService.parseSubject(token)` directly; it already throws jjwt's runtime exceptions (e.g. `ExpiredJwtException`, `SignatureException`) on invalid/expired tokens, which the filter should catch and turn into 401.
  - Still no JDK/`mvn`/network in this sandbox — could not run `./mvnw test`. Re-verify with a real JDK 21 environment before merge.
