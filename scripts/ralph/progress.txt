## Codebase Patterns
- Backend package-by-feature under `com.app.<feature>` (see docs/ARCHITECTURE.md); exception handlers use `@RestControllerAdvice(basePackages = "com.app.<feature>")` returning `Map<String,String>`/`Map<String,Object>` bodies (see com.app.auth.AuthExceptionHandler).
- `src/test/resources/application.properties` REPLACES `src/main/resources/application.properties` entirely for `@SpringBootTest` — it does NOT layer on top. It must redeclare every property any eagerly-instantiated bean needs (`tmdb.api-key` for TmdbConfig, `app.jwt.secret` for JwtService, `app.jwt.expiration-days` for JwtService). Adding a new required property to main application.properties means mirroring it in the test one too.
- This sandbox has no JDK/Maven installed and no Maven Central access — `./mvnw test`/`package` cannot be executed; code must be reviewed carefully by hand.
- `couple_id` must always be extracted from the authenticated user's context (SecurityContext → UserDetails → User entity → couple.id), never from the request body, to prevent cross-couple data access.
- All tracking endpoints require JWT (anyRequest().authenticated() in SecurityConfig) — no explicit permitAll needed for /api/tracking/**.
- com.app.media.MediaType enum (MOVIE, TV) already exists from Épico 3 — reuse it in com.app.tracking entities; do not redefine it.
- This codebase's existing entities (User, Couple) store raw UUID FK fields, not JPA relations — com.app.tracking.MediaTrack/UserReview are the first to use @ManyToOne/@OneToMany; follow that relation-based style within com.app.tracking since the PRD calls for it there specifically.
- spring.jpa.hibernate.ddl-auto=update was already set in application.properties before Épico 4 — no change needed for new entities to get their tables created.
