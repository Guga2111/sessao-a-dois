## Codebase Patterns
- `@ConfigurationProperties` classes in this codebase are plain `@Component` beans (no `@EnableConfigurationProperties`/`@ConfigurationPropertiesScan` registered anywhere) - component scan picks them up because they live under `com.app`.
- bucket4j 8.10.1 (`com.bucket4j:bucket4j-core`, Java package `io.github.bucket4j`) API used: `Bucket.builder().addLimit(Bandwidth.classic(capacity, Refill.intervally(capacity, window))).build()`, then `bucket.tryConsumeAndReturnRemaining(1)` -> `ConsumptionProbe.isConsumed()`/`getNanosToWaitForRefill()`. A record component accessor cannot share a zero-arg signature with a static factory method of the same name on that record (e.g. `record R(boolean allowed)` cannot also declare `static R allowed()`) - javac reports it as "invalid accessor method... must be public", which is misleading; rename the static factory instead.
- `@WebMvcTest(SomeController.class)` only loads the controller + explicitly `@Import`ed beans - any plain `@Component` a controller depends on (e.g. `ClientIpResolver`) must be added to the test's `@Import({...})` list or the context fails to wire it.
- In-memory rate-limit/cache services that key by arbitrary strings (IP, email, user id) should evict inactive entries via a `@Scheduled` sweep (app already has `@EnableScheduling` on `SessaoADoisApplication`) rather than relying on an external cache library - keeps the dependency footprint small for a single-instance 1 CPU / 512M deployment.

- Implemented rate-limiting infrastructure (bucket4j) without wiring it into any filter/endpoint yet (that's US-002/US-003):
  - Added `com.bucket4j:bucket4j-core:8.10.1` to `api/pom.xml`.
  - Created `com.app.security.ClientIpResolver` (reads first IP of `X-Forwarded-For`, falls back to `request.getRemoteAddr()`); removed the duplicate `AuthController.clientIp` private method and wired the new resolver into `AuthController` (login/refresh) via constructor injection.
  - Created `com.app.security.RateLimitProperties` (`@ConfigurationProperties(prefix = "app.rate-limit")`, plain `@Component`) exposing `enabled` plus a `Limit(capacity, window)` nested class for `login`, `register`, `refresh`, `coupleJoin`, `loginByEmail`, `coupleJoinByUser` - defaults match FR-2 (login 5/min IP, register 3/min IP, refresh 30/min IP, couple-join 5/min IP, login 10/hour email, couple-join 20/hour user).
  - Added the corresponding `app.rate-limit.*` properties to `api/src/main/resources/application.properties`, each overridable via `${VAR:default}` env vars, following the file's existing convention. No test-properties mirroring needed since every property already has a matching Java-side default on `RateLimitProperties`, and `RateLimitProperties` isn't `@Autowired` into anything with eager side effects yet.
  - Created `com.app.security.RateLimitService`: `tryConsume(String key, int capacity, Duration window)` resolves/creates a bucket per key (`ConcurrentHashMap<String, BucketHolder>`), returns `RateLimitResult(allowed, retryAfterSeconds)`. A `@Scheduled(fixedRate = 30min)` sweep evicts buckets untouched for 2 hours, so a key used once (e.g. an attacker's IP) doesn't leak memory forever.
