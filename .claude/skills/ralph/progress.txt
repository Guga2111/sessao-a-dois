- Frontend-only feature (client/). No backend/endpoint changes — reuse GET /api/media/{movie|tv}/{tmdbId} (MediaDetails).

- shadcn/base-ui Dialog usage: pass showCloseButton={false} + roll a custom close Button with a Portuguese aria-label, and always render <DialogTitle className="sr-only"> (base-ui Dialog.Popup needs an accessible name). See TitleModal.tsx / ComparisonDialog.tsx.

## 2026-08-01 - US-002
- Implemented shared-highlighting + higher-rating indicators in ComparisonDialog.tsx (client/src/components/ComparisonDialog.tsx), building on US-001's two-column layout.
- Added `sharedNames(a, b)` helper: case-insensitive name match between the two columns' genre lists / watch-provider name lists, returning a `Set<string>` of lowercased shared names, computed once in `ComparisonDialog` via `useMemo` (keyed on `left.genres`/`right.genres` and the mapped provider-name arrays) and passed down to both `ComparisonColumn`s as `sharedGenres`/`sharedProviders`.
- Added `higherSide(left, right)` helper: returns `"left" | "right" | null`, returning `null` whenever either value is `null` (so an absent rating never counts as "winning") or when the two values are equal (tie = no highlight). Used for both the Nota do Casal (`coupleRating`) and Nota TMDB (`voteAverage`) rows.
- Genre pills and watch-provider pills: shared items switch from the neutral pill style (`border-[rgba(255,255,255,.1)] bg-[rgba(255,255,255,.05)] text-[#d6d2c8]`) to the same gold pill treatment already used for the Filme/Série type badge (`border-[rgba(255,203,43,.25)] bg-[rgba(255,203,43,.12)] text-[#ffdd7a]`) — reused an existing token combo instead of inventing a new one. The watch-provider fallback dot (shown when a provider has no `logoUrl`) also switches color (gold when shared, `#a6a39a` gray otherwise) so the highlight reads correctly even without a logo.
- Rating rows: the winning column's value text turns `#ffcb2b` (from the default `#f6f4ec`/bold-white) and gets a small `ArrowUp` icon (`lucide-react`, `strokeWidth={3}`, `aria-hidden`) appended after the value — kept deliberately subtle per the AC's "indicador sutil" wording, no badge/pill/animation.
- `ComparisonColumn` now takes `side: "left" | "right"` plus the four comparison props (`sharedGenres`, `sharedProviders`, `coupleWinner`, `tmdbWinner`) and derives `isCoupleWinner`/`isTmdbWinner` by comparing `side` against the winner — same computed-once-in-parent, consumed-by-both-columns shape as the shared-name sets.
- Files changed: client/src/components/ComparisonDialog.tsx; scripts/ralph/prd.json, scripts/ralph/progress.txt, .claude/skills/ralph/prd.json, .claude/skills/ralph/progress.txt (also fixed the dual-location prd.json issue noted in Codebase Patterns above).
- Quality checks: `npm run typecheck` passes; `npx eslint src/components/ComparisonDialog.tsx` clean.
- **Learnings for future iterations:**
  - This story was pure enhancement of an already-established design system (US-001's gold/neutral pill tokens, existing rating-row layout) — frontend-design's guidance was to reuse those exact tokens for the "shared" state rather than invent a new highlight color, and keep the rating-winner indicator understated (text color + one small icon, not a badge/glow/animation).
  - "Ausente não conta como maior nem menor" was implemented as: if either side of a rating comparison is `null`, `higherSide` returns `null` and *neither* column gets the winner treatment — not "the non-null side automatically wins." Same `null`-safe rule applied to both Nota do Casal and Nota TMDB for consistency, even though the AC text only spelled it out for Nota do Casal (voteAverage is realistically always present from TMDB, but the type allows `null`).
  - Shared-name matching normalizes to lowercase for comparison but renders the *original* casing from each column's own `item.genres`/`item.watchProviders.name` — no cross-column name substitution, so e.g. "Ação" vs "ação" would both highlight but each column still displays its own original string.
  - No browser verification possible in this sandbox (same Chromium/Playwright gap as US-001) — manual verification still needed before merge.
